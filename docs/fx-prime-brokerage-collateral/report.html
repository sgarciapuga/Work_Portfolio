A reproducible walkthrough from synthetic FX data to Power BI

Executive summary

This report documents the FX Prime Brokerage Collateral project as a reproducible analysis. It walks through the Python pipeline, renders outputs from the generated CSV files, and connects those calculations to the Power BI semantic model and dashboard.

The project is synthetic and intended for portfolio demonstration and training. It is not a production margin or collateral engine.

Setup

Start by importing the required modules and loading the generated CSV files. The find_project_root() function locates the project folder based on the presence of data/ and src/ subfolders. The four datasets are read into a dictionary of DataFrames for later use.

The pipeline produces four core datasets: the FX portfolio, counterparty limits, mark-to-market data, and the final MTM collateral report.

from pathlib import Path

import matplotlib.pyplot as plt
import pandas as pd
from IPython.display import display


def find_project_root():
    candidates = [Path.cwd(), Path.cwd() / "fx-prime-brokerage-collateral"]
    for candidate in candidates:
        if (candidate / "data").is_dir() and (candidate / "src").is_dir():
            return candidate
    raise FileNotFoundError("Could not locate the FX collateral project folder")

What the pipeline produces

As a summary, the pipeline produces four core datasets: the FX portfolio, counterparty limits, mark-to-market data, and the final collateral report (mtm_report). Each serves a specific purpose in the overall workflow.

Dataset Grain Purpose
fx_portfolio trade leg and reporting date FX trades and USD portfolio size
limits counterparty and as-of date credit limit, exposure, and availability
mark_to_market_portfolio trade leg and reporting date daily FX movement and P&L
mtm_report reporting date margin, collateral, and excess/deficit

1. Understand the Python pipeline

Start with the modules

Each dataset is generated by a dedicated module, which is called in dependency order by the orchestrator generate_fx_datasets.py.

generate_fx_datasets.py calls the stages in order and optionally saves them to PostgreSQL the complete workflow

Stage 2: derive limits

generate_limits.py creates a limit schedule for each bank and subtracts the portfolio exposure from the limit:

limit_available_usd = credit_limit_usd - counterparty_exposure_usd

This is a control dataset, not a market valuation. It answers: how much unused counterparty capacity remains? If portfolio exposure exceeds the limit, available capacity becomes negative, indicating that no additional trades should be allocated to that bank until capacity is restored. In practice, a limit breach may restrict the bank’s ability to offer additional transactions until exposure drops back within limits.

2. Collateral mechanics and observed outputs

The calculation

The core logic lives in src/generate_mtm_report.py. For each business date:

  1. Initial margin is the minimum amount of cash or collateral deposited with a broker to support a leveraged position. For this synthetic model, initial margin is calculated as 5% of active trade exposure and is stored as a negative amount because it represents an obligation to the broker.
  2. Variation margin is the aggregated mark-to-market P&L. It keeps its market sign: positive means favourable revaluation and negative means adverse revaluation.
  3. Collateral required is the sum of initial margin and variation margin.
  4. Posted collateral is the amount already posted by the client to the broker.
  5. Excess/deficit compares posted collateral with the positive internal obligation. Negative means more collateral is needed; positive means excess collateral is held.
  6. A deficit schedules a next-day posting to reach the exposure plus a buffer (which is normally around $ 500K).
  7. A surplus above the buffer can trigger a collateral recall.
# Simplified calculation from generate_mtm_report.py
im_raw = 0.05 * exposure
vm_raw = daily_pnl
initial_margin = -im_raw
variation_margin = vm_raw
collateral_required = initial_margin + variation_margin
excess_deficit = collateral_required - collateral_posted

The current constants are INITIAL_COLLATERAL = 1_000_000, BUFFER = 500_000, MOVE_INCREMENT = 10_000, and MIN_MOVE = 50_000.

Visualisation: collateral KPI cards

The Power BI dashboard summarises the latest collateral position using KPI cards. The same metrics can be reproduced in Python for validation and comparison. The values retain the data-model sign convention. For example, Initial Margin and Collateral Required remain negative, while the card change shows the ordinary numerical difference from the previous date.

from matplotlib.patches import FancyBboxPatch


def format_amount(value):
    """Format a USD value compactly for a KPI card."""
    absolute_value = abs(value)
    if absolute_value >= 1_000_000:
        return f"{'-' if value < 0 else ''}{absolute_value / 1_000_000:.2f}M"
    if absolute_value >= 1_000:
        return f"{'-' if value < 0 else ''}{absolute_value / 1_000:.0f}K"
    return f"{value:,.0f}"


def format_change(value):
    """Format a numerical daily change with an ASCII direction marker."""
    if value > 0:
        return f"+ {format_amount(value)}"
    if value < 0:
        return f"- {format_amount(abs(value))}"
    return "- 0"


latest_date = mtm_report["report_date"].max()
report_dates = sorted(mtm_report["report_date"].unique())
previous_date = report_dates[-2] if len(report_dates) > 1 else latest_date
latest_report = mtm_report.loc[mtm_report["report_date"] == latest_date].iloc[0]
previous_report = mtm_report.loc[mtm_report["report_date"] == previous_date].iloc[0]

latest_portfolio = portfolio.loc[portfolio["report_date"] == latest_date]
previous_portfolio = portfolio.loc[portfolio["report_date"] == previous_date]

cards = [
    ("Initial Margin", latest_report["initial_margin"], latest_report["initial_margin"] - previous_report["initial_margin"]),
    ("Variation Margin", latest_report["variation_margin"], latest_report["variation_margin"] - previous_report["variation_margin"]),
    ("Collateral Required", latest_report["collateral_required"], latest_report["collateral_required"] - previous_report["collateral_required"]),
    ("Collateral Posted", latest_report["collateral_posted"], latest_report["collateral_posted"] - previous_report["collateral_posted"]),
    ("Excess / Deficit", latest_report["excess_deficit"], latest_report["excess_deficit"] - previous_report["excess_deficit"]),
    ("Total Portfolio (USD)", latest_portfolio["trade_size_usd"].sum(), latest_portfolio["trade_size_usd"].sum() - previous_portfolio["trade_size_usd"].sum()),
    ("Open Positions", latest_portfolio["trade_id"].nunique(), latest_portfolio["trade_id"].nunique() - previous_portfolio["trade_id"].nunique()),
]

3. Power BI documentation

Project structure

The checked-in PBIP project is under fx-prime-brokerage-collateral/dashboard/:

dashboard/
├── fx-prime-brokerage-collateral.pbip
├── fx-prime-brokerage-collateral.Report/
│   └── definition/pages/
└── fx-prime-brokerage-collateral.SemanticModel/
    └── definition/
        ├── tables/
        ├── relationships.tmdl
        └── model.tmdl

The model contains three principal facts (fx_portfolio, limits, mtm_report), supporting dimensions (dim_date, dim_banks, dim_currencies), an FX rates table, and Measures_Table for reusable DAX.

Relationship and filter design

The date dimension filters mtm_report.report_date, fx_portfolio.report_date, and limits.as_of_date. Bank and currency dimensions provide reusable slicer paths. The collateral page should therefore use dim_date[calendar_date] for time controls rather than placing the fact date directly in every visual.

The primary modelling caveat is grain: mtm_report is daily, while fx_portfolio is trade-leg level. Measures must be used when combining these tables so that a visual does not accidentally sum a daily collateral value once per trade.

Core DAX measures

These are the central measures already present in Measures_Table.tmdl:

Initial Margin = SUM(mtm_report[initial_margin])
Variation Margin = SUM(mtm_report[variation_margin])
Collateral Required = SUM(mtm_report[collateral_required])
Collateral Posted = SUM(mtm_report[collateral_posted])
Excess / Deficit = SUM(mtm_report[excess_deficit])

Because initial margin and collateral required are stored as negative amounts owed to the broker, inverse measures can be useful for visuals where positive means amount required.

Initial Margin (Inverse) = -1 * SUM(mtm_report[initial_margin])

Collateral Required (Inverse) = -1 * SUM(mtm_report[collateral_required])

Previous-day and moving-average patterns

The previous-day pattern finds the latest fact date before the current date selected in the date dimension, then evaluates the measure at that date:

Collateral Posted (Previous Day) =
VAR CurrentDate = MAX(dim_date[calendar_date])
VAR PreviousDateWithData =
    CALCULATE(
        MAX(mtm_report[report_date]),
        REMOVEFILTERS(dim_date),
        dim_date[calendar_date] < CurrentDate
    )
RETURN
    CALCULATE(
        [Collateral Posted],
        REMOVEFILTERS(dim_date),
        dim_date[calendar_date] = PreviousDateWithData
    )

Collateral Posted (Daily Change) =
    [Collateral Posted] - [Collateral Posted (Previous Day)]

For smoothing, the existing model uses a 30-day window:

IM 30 Day Moving Average =
CALCULATE(
    AVERAGEX(
        DATESINPERIOD(
            dim_date[calendar_date],
            MAX(dim_date[calendar_date]),
            -30,
            DAY
        ),
        [Initial Margin (Inverse)]
    )
)

Practical validation checklist

  1. Refresh the source data and confirm the four CSV row counts remain stable on a repeat run.
  2. Check that dim_date filters all date-bearing facts at the intended grain.
  3. Confirm inverse measures are used only where positive values mean required or adverse exposure.
  4. Compare the Power BI latest-date KPI with the last row of mtm_report.csv.
  5. Check that a counterparty or date slicer does not duplicate daily collateral totals.

Conclusion

The project provides an end-to-end narrative from synthetic data generation to collateral calculation and dashboard consumption. Python creates deterministic analytical datasets, the collateral report applies explicit sign and movement rules, and Power BI transforms those datasets into reusable measures and interactive monitoring views. The Quarto report provides the reproducible audit trail connecting these layers.

## What the pipeline produces

As a summary, the pipeline produces four core datasets: the FX portfolio, counterparty limits, mark-to-market data, and the final collateral report (mtm_report). Each serves a specific purpose in the overall workflow.

| Dataset | Grain | Purpose |
|------------------------|------------------------|------------------------|
| `fx_portfolio` | trade leg and reporting date | FX trades and USD portfolio size |
| `limits` | counterparty and as-of date | credit limit, exposure, and availability |
| `mark_to_market_portfolio` | trade leg and reporting date | daily FX movement and P&L |
| `mtm_report` | reporting date | margin, collateral, and excess/deficit |

# 1. Understand the Python pipeline

## Start with the modules

Each dataset is generated by a dedicated module, which is called in dependency order by the orchestrator `generate_fx_datasets.py`.

| Module | What it does | Output used by |
|------------------------|------------------------|------------------------|
| `generate_fx_portfolio.py` | creates trade legs, dates, currency pairs, and bank assignments | limits and portfolio MTM |
| `generate_limits.py` | creates counterparty credit limits and calculates available capacity | portfolio generation and the Limits page |
| `generate_mtm_for_portfolio.py` | simulates daily MTM and P&L for the generated portfolio | collateral report |
| `generate_mtm_report.py` | applies margin, collateral, buffer, and deficit/recall rules | dashboard and analysis |
| `generate_fx_datasets.py` | calls the stages in order and optionally saves them to PostgreSQL | the complete workflow |

The dependency direction is:

Daily data is required to calculate the portfolio size in USD for each currency pair. This size is later used to calculate the different elements of the collateral report.

## Stage 2: derive limits

`generate_limits.py` creates a limit schedule for each bank and subtracts the portfolio exposure from the limit:

``` python
limit_available_usd = credit_limit_usd - counterparty_exposure_usd
```

This is a control dataset, not a market valuation. It answers: **how much unused counterparty capacity remains?** If portfolio exposure exceeds the limit, available capacity becomes negative, indicating that no additional trades should be allocated to that bank until capacity is restored. In practice, a limit breach may restrict the bank's ability to offer additional transactions until exposure drops back within limits.

## Stage 3: calculate mark-to-market

`generate_mtm_for_portfolio.py` takes each active portfolio trade and creates a reproducible random-walk MTM series until settlement. P&L is then scaled by trade size:

``` python
pnl = mtm * trade_size_usd
```

This makes the output useful for demonstrating aggregation and visualisation without presenting the synthetic values as real market data.

`generate_fx_datasets.py` is the entry point. Its job is coordination: call the generators in dependency order, write the four CSV files, and, when `DATABASE_URL` is configured, upsert the same datasets into PostgreSQL. # 2. Collateral mechanics and observed outputs

## The calculation

```{mermaid}
%%| label: fig-pipeline
%%| fig-cap: "Collateral Process Flow"
%%| echo: false
flowchart TD
    A[Active portfolio exposure] --> B[Initial Margin<br/>5% of exposure]
    C[Daily MTM / P&L] --> D[Variation Margin]

    B --> E[Collateral Required]
    D --> E

    E --> F[Compare with<br/>Collateral Posted]

    F --> G{Excess / Deficit}

    G -->|Deficit| H[Schedule next-day posting]
    H --> I[Exposure + buffer]

    G -->|Surplus| J{Above recall buffer?}
    J -->|Yes| K[Potential collateral recall]
    J -->|No| L[No movement]
```

The core logic lives in `src/generate_mtm_report.py`. For each business date:

1.  Initial margin is the minimum amount of cash or collateral deposited with a broker to support a leveraged position. For this synthetic model, initial margin is calculated as 5% of active trade exposure and is stored as a negative amount because it represents an obligation to the broker.
2.  Variation margin is the aggregated mark-to-market P&L. It keeps its market sign: positive means favourable revaluation and negative means adverse revaluation.
3.  Collateral required is the sum of initial margin and variation margin.
4.  Posted collateral is the amount already posted by the client to the broker.
5.  Excess/deficit compares posted collateral with the positive internal obligation. Negative means more collateral is needed; positive means excess collateral is held.
6.  A deficit schedules a next-day posting to reach the exposure plus a buffer (which is normally around \$ 500K).
7.  A surplus above the buffer can trigger a collateral recall.

``` python
# Simplified calculation from generate_mtm_report.py
im_raw = 0.05 * exposure
vm_raw = daily_pnl
initial_margin = -im_raw
variation_margin = vm_raw
collateral_required = initial_margin + variation_margin
excess_deficit = collateral_required - collateral_posted   
```

The current constants are `INITIAL_COLLATERAL = 1_000_000`, `BUFFER = 500_000`, `MOVE_INCREMENT = 10_000`, and `MIN_MOVE = 50_000`.

## Visualisation: collateral KPI cards

The Power BI dashboard summarises the latest collateral position using KPI cards. The same metrics can be reproduced in Python for validation and comparison. The values retain the data-model sign convention. For example, Initial Margin and Collateral Required remain negative, while the card change shows the ordinary numerical difference from the previous date.

```{python}
#| label: collateral-kpi-cards
from matplotlib.patches import FancyBboxPatch


def format_amount(value):
    """Format a USD value compactly for a KPI card."""
    absolute_value = abs(value)
    if absolute_value >= 1_000_000:
        return f"{'-' if value < 0 else ''}{absolute_value / 1_000_000:.2f}M"
    if absolute_value >= 1_000:
        return f"{'-' if value < 0 else ''}{absolute_value / 1_000:.0f}K"
    return f"{value:,.0f}"


def format_change(value):
    """Format a numerical daily change with an ASCII direction marker."""
    if value > 0:
        return f"+ {format_amount(value)}"
    if value < 0:
        return f"- {format_amount(abs(value))}"
    return "- 0"


latest_date = mtm_report["report_date"].max()
report_dates = sorted(mtm_report["report_date"].unique())
previous_date = report_dates[-2] if len(report_dates) > 1 else latest_date
latest_report = mtm_report.loc[mtm_report["report_date"] == latest_date].iloc[0]
previous_report = mtm_report.loc[mtm_report["report_date"] == previous_date].iloc[0]

latest_portfolio = portfolio.loc[portfolio["report_date"] == latest_date]
previous_portfolio = portfolio.loc[portfolio["report_date"] == previous_date]

cards = [
    ("Initial Margin", latest_report["initial_margin"], latest_report["initial_margin"] - previous_report["initial_margin"]),
    ("Variation Margin", latest_report["variation_margin"], latest_report["variation_margin"] - previous_report["variation_margin"]),
    ("Collateral Required", latest_report["collateral_required"], latest_report["collateral_required"] - previous_report["collateral_required"]),
    ("Collateral Posted", latest_report["collateral_posted"], latest_report["collateral_posted"] - previous_report["collateral_posted"]),
    ("Excess / Deficit", latest_report["excess_deficit"], latest_report["excess_deficit"] - previous_report["excess_deficit"]),
    ("Total Portfolio (USD)", latest_portfolio["trade_size_usd"].sum(), latest_portfolio["trade_size_usd"].sum() - previous_portfolio["trade_size_usd"].sum()),
    ("Open Positions", latest_portfolio["trade_id"].nunique(), latest_portfolio["trade_id"].nunique() - previous_portfolio["trade_id"].nunique()),
]

fig, axes = plt.subplots(1, len(cards), figsize=(19, 2.2))
fig.patch.set_facecolor("#f1f2ed")

for ax, (title, value, change) in zip(axes, cards):
    ax.set_xlim(0, 1)
    ax.set_ylim(0, 1)
    ax.axis("off")
    ax.add_patch(
        FancyBboxPatch(
            (0.01, 0.03),
            0.98,
            0.94,
            boxstyle="round,pad=0.015,rounding_size=0.04",
            linewidth=0.8,
            edgecolor="#d9ddd5",
            facecolor="#ffffff",
        )
    )
    value_color = "#1f7a4d" if value >= 0 else "#8b1e2d"
    change_color = "#1f7a4d" if change >= 0 else "#8b1e2d"
    ax.text(0.08, 0.79, title, fontsize=10, color="#6b6f6b", va="center")
    ax.text(0.08, 0.52, format_amount(value), fontsize=17, fontweight="bold", color=value_color, va="center")
    ax.text(0.08, 0.20, f"Change: {format_change(change)}", fontsize=9, color=change_color, va="center")

fig.suptitle(
    f"Collateral snapshot | {latest_date.date()}",
    x=0.01,
    y=1.08,
    ha="left",
    fontsize=12,
    fontweight="bold",
    color="#333333",

plt.show()
```

# 3. Power BI documentation

## Project structure

The checked-in PBIP project is under `fx-prime-brokerage-collateral/dashboard/`:

``` text
dashboard/
├── fx-prime-brokerage-collateral.pbip
├── fx-prime-brokerage-collateral.Report/
│   └── definition/pages/
└── fx-prime-brokerage-collateral.SemanticModel/
    └── definition/
        ├── tables/
        ├── relationships.tmdl
        └── model.tmdl
```

The model contains three principal facts (`fx_portfolio`, `limits`, `mtm_report`), supporting dimensions (`dim_date`, `dim_banks`, `dim_currencies`), an FX rates table, and `Measures_Table` for reusable DAX.

## Relationship and filter design

The date dimension filters `mtm_report.report_date`, `fx_portfolio.report_date`, and `limits.as_of_date`. Bank and currency dimensions provide reusable slicer paths. The collateral page should therefore use `dim_date[calendar_date]` for time controls rather than placing the fact date directly in every visual.

The primary modelling caveat is grain: `mtm_report` is daily, while `fx_portfolio` is trade-leg level. Measures must be used when combining these tables so that a visual does not accidentally sum a daily collateral value once per trade.

## Core DAX measures

These are the central measures already present in `Measures_Table.tmdl`:

``` dax
Initial Margin = SUM(mtm_report[initial_margin])
Variation Margin = SUM(mtm_report[variation_margin])
Collateral Required = SUM(mtm_report[collateral_required])
Collateral Posted = SUM(mtm_report[collateral_posted])
Excess / Deficit = SUM(mtm_report[excess_deficit])
```

Because initial margin and collateral required are stored as negative amounts owed to the broker, inverse measures can be useful for visuals where positive means amount required.

``` dax
Initial Margin (Inverse) = -1 * SUM(mtm_report[initial_margin])

Collateral Required (Inverse) = -1 * SUM(mtm_report[collateral_required])
```

## Previous-day and moving-average patterns

The previous-day pattern finds the latest fact date before the current date selected in the date dimension, then evaluates the measure at that date:

``` dax
Collateral Posted (Previous Day) =
VAR CurrentDate = MAX(dim_date[calendar_date])
VAR PreviousDateWithData =
    CALCULATE(
        MAX(mtm_report[report_date]),
        REMOVEFILTERS(dim_date),
        dim_date[calendar_date] < CurrentDate
    )
RETURN
    CALCULATE(
        [Collateral Posted],
        REMOVEFILTERS(dim_date),
        dim_date[calendar_date] = PreviousDateWithData
    )

Collateral Posted (Daily Change) =
    [Collateral Posted] - [Collateral Posted (Previous Day)]
    
```

For smoothing, the existing model uses a 30-day window:

``` dax
IM 30 Day Moving Average =
CALCULATE(
    AVERAGEX(
        DATESINPERIOD(
            dim_date[calendar_date],
            MAX(dim_date[calendar_date]),
            -30,
            DAY
        ),
        [Initial Margin (Inverse)]
    )
)
```
